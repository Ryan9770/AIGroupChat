# 픽셀 관성 인쇄 — 개선 토론 결과

## 1. 토론 개요

- 주제: 인기 있는 2D 픽셀 그래픽 요소와 건전한 보상 구조를 결합해 새로운 게임 장르를 만들고, Godot 4.x 프로토타입으로 구체화한다.
- 방식: Antigravity와 Codex가 네 관점을 번갈아 맡아 16턴 토론하고 Codex가 최종 정리했다.
- 관점: 시장·장르 분석, 시스템 설계, 플레이어 경험 비평, Godot 기술 설계
- 제약: 8턴 전 단일안 확정 금지, 최소 네 후보 유지, 13턴 이후 최종 선택, 검증되지 않은 주장은 가정으로 표시
- 목표: PC 싱글플레이, 8주 안에 핵심 재미와 기술 위험을 검증하는 프로토타입

이 문서는 개선된 실제 토론에서 나온 후보, 결정, 근거, 이견과 구현 계획을 실행 가능한 형태로 다시 정리한 것이다. 시장성에 관한 인과 해석은 별도 검증 전까지 가설로 취급한다.

| 3 | 픽셀 분광 물성 변환 | 채취·분광·변환 | 픽셀 색·스펙트럼으로 물성을 바꾼다 | 색상 규칙의 가독성과 콘텐츠 제작비 | 보류 |

## 3. 비교 기준과 결과

8턴에 다음 가중치를 합의했다.

| 기준 | 가중치 |
|---|---:|
| 새로움 | 15 |
| 30초 안에 이해되는가 | 10 |
| 숙련·전략 깊이 | 15 |
| 반복 플레이 가능성 | 15 |
| 비강박적 보상 구조 | 10 |
| 픽셀 그래픽과 규칙의 결합 | 10 |

토론 중 산정한 총점 가설은 후보 1부터 각각 70, 81, 74, 76, 83이었다. 후보 5가 새로움, 규칙의 시각화, 짧은 피드백 루프, 구현 범위의 균형에서 가장 높게 평가됐다. 다만 항목별 원점수는 토론 기록에 모두 남지 않았으므로 이 총점은 재현 가능한 확정 평가가 아니라 의사결정 보조치다.

## 4. 최종 선택안

### 장르명

운동량 편집 액션 퍼즐

### 작업명

픽셀 관성 인쇄

### 한 문장 설명

움직이는 물체의 운동 벡터를 픽셀 띠로 수집한 뒤 플레이어, 사물, 기믹에 인쇄하여 운동량 보존과 반작용으로 이동 규칙을 재배선하는 2D 액션 퍼즐이다.

### 핵심 동사

1. 수집: 움직이는 대상에서 방향과 세기가 양자화된 관성 띠를 얻는다.
2. 인쇄: 저장한 관성을 자신이나 다른 대상에 적용한다.
3. 편향: 충돌, 반작용, 지형을 이용해 예상 경로를 바꾼다.

## 5. 30초 플레이 루프

1. 궤적과 위험을 읽는다.
2. 움직이는 물체에 접근해 관성 벡터를 수집한다.
3. 약 0.2배속 조준 상태에서 대상과 방향을 고른다.
4. 적용 후 궤적과 충돌 결과를 미리 본다.
5. 관성을 인쇄한다.
6. 충돌과 연쇄 반응을 관찰한다.
7. 성공 또는 실패 원인을 즉시 이해하고 다음 시도를 수정한다.

프로토타입에서는 방향을 8개, 세기를 3단계로 제한하고 저장 슬롯은 최대 3개로 둔다. 연속 물리량을 그대로 다루는 대신 읽고 예측할 수 있는 규칙을 우선한다.

## 6. 보상 구조

### 순간 보상

- 인쇄 순간의 픽셀 띠, 잔상, 충돌음과 짧은 정지 효과
- 예상 궤적과 실제 결과의 즉각 비교
- 한 번의 인쇄로 여러 물체가 연결될 때 강화되는 시청각 피드백

### 단기 보상

- 방 하나를 여러 방식으로 해결
- 적은 인쇄 횟수, 짧은 시간, 피해 없음 같은 선택 과제
- 실패 직후 원인이 보이는 빠른 재시도

### 중기 보상

- 새로운 벡터 조합과 환경 기믹 해금
- 플레이어가 발견한 해결법을 기록하는 도감
- 더 정확한 계획과 적은 조작으로 이어지는 숙련감

무작위 보상, 연속 접속 압박, 손실 회피성 재화, 유료 확률 상품은 MVP에서 제외한다. 보상은 체류 시간 자체보다 이해, 숙련, 자기표현에 연결한다.

### 제외

- 장기 성장 경제와 방대한 서사

## 8. Godot 4.x 구현안

### 물리 원칙

- 핵심 이동은 `CharacterBody2D`와 `move_and_collide()`를 이용해 고정 순서로 처리한다.
- 핵심 규칙에는 `RigidBody2D`의 비결정적 상호작용을 사용하지 않는다.
- `_physics_process()`의 고정 틱에서 입력, 이동, 충돌, 반작용, 상태 해시 순으로 계산한다.
- 고속 이동은 한 프레임을 여러 하위 단계로 나누거나 스윕 테스트로 충돌 누락을 방지한다.
- 동일 입력과 시드에서 같은 상태 해시가 나오는 것을 최우선 기술 조건으로 둔다.

### 권장 장면 구조

```text
Main
├─ World
│  ├─ Player
│  ├─ MomentumSources
│  ├─ MovableObjects
│  ├─ Hazards
│  └─ Goal
├─ SimulationController
├─ MomentumInventory
├─ TrajectoryPreview
├─ ReplayRecorder
├─ FeedbackController
└─ UI
```

### 핵심 데이터 모델

```gdscript
class_name MomentumStamp
extends Resource

@export var direction_index: int
@export var magnitude_level: int
@export var source_type: StringName
@export var reaction_rule: StringName
```

방향과 세기는 정수 ID로 저장한다. 시뮬레이션 상태에는 객체 ID, 위치, 현재 벡터, 활성 규칙, 틱 번호를 포함하고 매 틱 또는 중요 사건마다 해시를 남긴다.

## 10. 검증 지표와 중단 기준

다음 중 하나라도 충족하면 현재 설계를 그대로 확장하지 않고 원인을 수정하거나 후보 2로 피벗한다.

- 동일 입력 리플레이의 상태 해시 불일치가 한 번 이상 발생한다.
- 신규 테스트 참가자 10명 중 30초 안에 첫 인쇄에 성공한 비율이 60% 미만이다.
- 운동량 상쇄 한 가지 해법이 전체 성공 사례의 40%를 초과한다.
- 참가자가 실패 원인을 설명하지 못하거나 반작용 방향을 반복적으로 오해한다.
- 목표 하드웨어에서 물리 틱 또는 프레임 시간이 정한 예산을 지속적으로 넘는다.

피벗 시에는 잔상 직조 잠입을 우선 검토한다. 이 후보는 물리 결정론 위험이 더 낮지만, 대기와 반복 입력의 지루함을 별도로 검증해야 한다.

## 12. 토론 품질 판정

이번 토론은 이전 실행보다 다음 점에서 개선됐다.

- 다섯 후보의 이름과 상태가 최종 보고서까지 유지됐다.
- 8턴 전 조기 수렴을 피하고 비교 기준을 먼저 만들었다.
- 최종 선택과 2순위 피벗 후보를 구분했다.
- 시장 근거와 설계 가정을 분리했다.
- Godot 구현 위험, 8주 범위, 중단 기준을 한 결론에 연결했다.
- 서기가 최근 발언만이 아니라 전체 16턴을 바탕으로 정리했다.

남은 약점도 있다. 각 후보의 항목별 점수가 기록되지 않아 총점 재산정이 어렵고, 역할별 최종 투표 시점이 완전히 통일되지 않았다. 다음 토론부터는 12턴에 모든 역할의 투표를 별도 구조화 입력으로 수집하고, 항목별 점수와 근거를 JSON 또는 표로 저장하는 편이 좋다.

## 13. 실제 실행 사용량

| 항목 | 토큰 |
|---|---:|
| 입력 | 319,848 |
| 출력 | 76,384 |
| 캐시 읽기 | 139,612 |
| 캐시 생성 | 0 |

- 발언 16회, 서기 정리 1회로 총 17회 호출했다.
- 사용량 이벤트는 17/17회 수신되어 누락이 없다.
- Provider가 금액을 반환하지 않아 실제 누적 비용은 산정되지 않았다. 화면의 `$0`을 무료 사용으로 해석하면 안 된다.

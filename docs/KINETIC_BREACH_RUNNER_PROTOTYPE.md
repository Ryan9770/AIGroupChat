# 키네틱 절개 탈출 프로토타입 기획 정리

## 1. 문서 목적과 상태

이 문서는 16턴 모델 토론에서 도출된 게임 후보와 최종 선택안을 하나의 실행 가능한 프로토타입 계획으로 정리한다.

- 프로젝트 상태: 콘셉트 가설
- 개발 목표: Godot 4.x 기반 8주 PC 싱글플레이 프로토타입
- 최우선 검증 질문: 절개로 발생한 반동 이동과 누출 관리가 단일 방에서도 반복하고 싶은 조작 재미를 만드는가?
- 확정되지 않은 항목: 시장성, 세션 길이, 수치 밸런스, 목표 해상도, 압력 갱신 주기

현재 선택안은 완성된 장르가 아니라 가장 먼저 검증할 가치가 있다고 판단한 프로토타입 후보다.

## 2. 토론에서 검토한 후보

### 2.1 절개항해

- 장르 정의: 지형을 절개하고 봉합해 압력과 누출을 제어하는 2D 물리 경로 편집 액션
- 핵심 동사: 절개, 추진, 봉합
- 차별점: 하나의 절개가 길, 자원, 이동 반동과 위험 누출을 동시에 만든다.
- 주요 보상: 정밀 조작 숙련, 경로 발견, 위험 관리, 자율적 정산
- 픽셀 그래픽 역할: 재질 셀, 절개 범위, 파편, 압력 상태와 충돌 판정을 명확히 표현
- 가장 큰 위험: 파괴와 압력 계산의 기술 비용, 예측하기 어려운 급사
- 판단: 최종 프로토타입 후보로 채택

### 2.2 잔향직조

- 장르 정의: 짧은 행동 기록을 잔향으로 재생해 현재 플레이어와 협동하는 1인 동시 행동 액션
- 핵심 동사: 기록, 배치, 동기화
- 차별점: 과거 행동이 현재의 협동자이자 도구가 된다.
- 주요 보상: 타이밍 숙련, 공간 해법 발견, 합동 행동 성공
- 픽셀 그래픽 역할: 프레임 단위 동기화 오차와 행동 궤적을 선명하게 표현
- 가장 큰 위험: 최적 해법 발견 후 반복 플레이가 암기형 실행으로 굳을 수 있음
- 판단: 기술 위험이 낮은 대체 프로토타입으로 유지

### 2.3 생태운반

- 장르 정의: 생물을 포획, 운반, 유인, 이식해 지형과 먹이망을 바꾸는 생태 조작 액션
- 핵심 동사: 관찰, 유인, 운반, 배치
- 차별점: 전투보다 생태 관계의 재배치가 진행 규칙을 바꾼다.
- 주요 보상: 상호작용 발견, 도감 지식, 생태계 안정화
- 픽셀 그래픽 역할: 생물의 상태와 먹이사슬 관계를 색과 실루엣으로 전달
- 가장 큰 위험: AI, 먹이망, 레벨 설계를 동시에 검증해야 하며 운반이 반복 노동이 될 수 있음
- 판단: 8주 범위를 초과할 가능성이 높아 보류

### 2.4 흔적역류

- 장르 정의: 플레이어의 이동은 유지한 채 선택한 타일의 최근 상태만 되감는 국소 시간 편집 액션
- 핵심 동사: 유인, 파괴 유도, 국소 복원, 통과
- 차별점: 전체 시간이 아니라 세계의 일부 상태만 되돌린다.
- 주요 보상: 인과 해석, 창의적인 상태 조합, 경로 해결
- 픽셀 그래픽 역할: 타일 단위 전후 상태와 되감기 범위를 명확히 표현
- 가장 큰 위험: 상태 저장, 모순 처리, 프리뷰와 인지 부하
- 판단: 새로움은 높지만 기술 및 온보딩 위험이 커서 보류

## 3. 후보 선택 근거

절개항해는 다음 이유로 첫 프로토타입 후보가 되었다.

1. 절개라는 한 행동이 이동, 보상과 위험을 동시에 발생시켜 중심 규칙을 한 문장으로 설명할 수 있다.
2. 픽셀 그래픽이 단순한 외형이 아니라 재질, 파괴 범위, 압력과 충돌 정보를 표현하는 규칙 인터페이스로 사용된다.
3. 순간 조작 보상과 세션 단위의 귀환 판단을 같은 누출 시스템으로 연결할 수 있다.
4. 실제 유체를 제외하고 압력 그래프로 축소하면 Godot 4.x에서 기술 검증이 가능하다.

다만 후보 비교 당시 사용한 정성 점수에는 사용자 조사나 플레이테스트 근거가 없다. 선택은 시장 성공 예측이 아니라 프로토타입 우선순위 결정이다.

## 4. 최종 콘셉트

### 장르명

키네틱 절개 탈출, 가칭 절개항해

### 한 문장 정의

고압 폐쇄 구역을 절개해 자원과 추진 반동을 얻고, 자신이 만든 누출 압력을 봉합하며 표본을 확보해 귀환하는 2D 물리 경로 편집 액션이다.

### 플레이어 판타지

플레이어는 위험한 폐쇄 구역에서 물리 법칙을 도구로 사용하는 기술 탐험가다. 벽을 부수는 것이 아니라 필요한 만큼 절개하고, 발생한 압력을 추진력으로 활용하며, 감당할 수 없는 누출은 봉합한다.

### 설계 기둥

1. 행동과 대가: 모든 유용한 절개는 동시에 위험과 복구 비용을 만든다.
2. 읽을 수 있는 위험: 압력과 누출은 색, 실루엣, 궤적과 음향으로 예고한다.
3. 자율적 정산: 플레이어가 확보와 추가 탐사의 시점을 직접 결정한다.
4. 횡적 성장: 장기 진행은 공격력 증가보다 새로운 도구와 상호작용을 해금한다.
5. 제한된 범위: 실제 유체, 복잡한 적 AI와 완전 절차 생성 없이 핵심 재미부터 검증한다.

## 5. 플레이 루프

### 5.1 30초 코어 루프

1. 취약 재질, 자원과 압력 방향을 읽는다.
2. 절개 위치와 폭을 선택한다.
3. 벽이 파단되며 누출과 반동이 발생한다.
4. 반동을 이용해 이동하거나 자원과 표본에 접근한다.
5. 누출을 봉합할지, 추가 절개로 전진할지, 퇴각할지 결정한다.
6. 픽셀 파편, 압력색, 궤적과 사운드로 결과를 확인한다.

### 5.2 구간 루프

- 저압 공간을 정찰한다.
- 압력원, 취약 재질과 자원 위치의 관계를 파악한다.
- 절개와 봉합으로 이동 경로를 편집한다.
- 런 내 횡적 강화 하나를 선택한다.
- 감압실에서 확보 자원을 사출한다.
- 귀환하거나 더 깊은 구역을 탐사한다.

### 5.3 세션 루프

- 시작: 도구 선택과 저압 정찰
- 성장: 절개 폭, 봉합 특성, 반동 변환 등 런 내 선택
- 위기: 누출망이 커지고 기존 귀환로가 변형됨
- 종료: 핵심 표본 회수 후 탈출, 중도 정산, 압력 붕괴 또는 체력 소진

20~40분 세션은 초기 가설이며 프로토타입에서 확정하지 않는다.

## 6. 보상과 위험 설계

### 순간 보상

- 절개 파단과 픽셀 파편
- 반동 이동 성공
- 예측한 압력 변화가 실제 결과와 일치하는 경험
- 재질과 누출 상태를 읽어낸 숙련감

### 구간 보상

- 새로운 경로 발견
- 표본과 자원 확보
- 런 내 도구 변형
- 감압실 도달과 안전한 자원 사출

### 장기 보상

- 새 도구와 기믹 해금
- 시작 조건 선택 확대
- 압력, 재질과 지형 관계에 대한 지식 축적
- 서로 다른 절개 및 봉합 스타일의 표현

### 손실 완화

- 감압실에서 사출한 자원은 100% 보존한다.
- 실패 시 미사출 자원만 위험에 노출한다.
- 추가 탐사는 강제가 아닌 플레이어 선택이다.
- 영구 능력치 파밍과 유료 확률 보상은 사용하지 않는다.

### 지배 전략 방지 가설

- 봉합재를 제한된 환경 소모 자원으로 둔다.
- 큰 절개는 높은 추진력과 접근성을 주지만 누출량과 봉합 비용도 증가시킨다.
- 압력은 임의 타이머가 아니라 플레이어가 만든 누출 총량에 연동한다.
- 작은 절개와 반복 봉합이 최적해가 되는지는 플레이테스트로 검증한다.

## 7. 온보딩과 피드백

### 온보딩 순서

1. 저압 구역에서 봉합 없이 절개 반동만 학습한다.
2. 다음 구역에서 누출과 봉합을 추가한다.
3. 감압실에서 자원 사출과 추가 탐사 선택을 소개한다.
4. 마지막으로 여러 압력원과 봉합 불가 재질을 조합한다.

### 표현 원칙

- 색만 사용하지 않고 실루엣과 패턴을 함께 사용한다.
- 절개 전에 예상 파단 범위와 반동 궤적을 표시한다.
- 절개 순간의 슬로모션은 초기 테스트 가설로만 취급한다.
- 논리 압력과 화면 효과가 다르게 보이지 않도록 디버그 오버레이를 제공한다.

## 9. Godot 4.x 기술 구조

### Scene 개요

```text
Main
|- RunManager
|- Room
|  |- TileMapLayer
|  |- PressureGraph
|  |- BreachContainer
|  |- SealContainer
|  |- PressureSourceContainer
|  `- RewardContainer
|- Player
|- FX
`- UI
```

### 주요 책임

- RunManager: 런 상태, 자원, 표본, 강화, 성공, 실패와 정산
- PlayerController: 입력, 이동, 반동과 도구 사용
- RoomController: 방 템플릿, 타일 상태와 제약 배치
- PressureGraph: 논리 셀 연결, 압력원, 누출량과 봉합 상태 계산
- Breach: 누출 생성과 PressureGraph 등록
- Seal: 봉합재 소비와 누출 차단
- SaveManager: 버전 필드가 있는 메타 해금 저장과 마이그레이션
- UIController: 압력, 봉합재, 사출 및 미사출 자원 표시
- DebugOverlay: 셀 압력, 누출망, 프레임 시간과 사망 원인 표시

### 주요 Godot 요소

- CharacterBody2D: 플레이어 이동과 반동
- TileMapLayer: 제한된 지형 교체와 충돌
- Area2D: Breach, Seal과 상호작용 영역
- Resource: 도구, 재질, 압력원, 보상과 해금 데이터
- Signal: 절개, 누출, 봉합, 압력 변화, 정산과 사망 이벤트
- AnimationPlayer: 절개 및 봉합 타이밍 연출
- GPUParticles2D: 픽셀 파편과 압력 효과
- Shader: 재질 및 압력 상태의 화면 보간

### 계산 원칙

- 실제 유체 대신 제한된 논리 셀 그래프를 사용한다.
- 압력 계산은 렌더 프레임과 분리된 고정 주기로 처리한다.
- 화면 사이 변화는 파티클과 셰이더로 보간한다.
- 타일 충돌 갱신 범위와 한 프레임 처리량에 상한을 둔다.
- 동일 입력에서 동일 압력 결과가 나오도록 결정성을 우선한다.

## 10. 8주 개발 계획

### 1주차: 기술 게이트

- 단일 방에서 절개, 압력 전파, 반동과 봉합 연결
- 목표 하드웨어와 해상도를 명시한 뒤 60FPS 검증
- 판정 재현성과 TileMapLayer 충돌 갱신 비용 측정
- 실패 시 압력 그래프 단순화 또는 잔향직조 전환 검토

### 2주차: 조작과 카메라

- 키보드 및 게임패드 입력
- 반동 이동과 절개 조준
- 픽셀 퍼펙트 카메라
- 절개 결과 예고와 궤적 표시

### 3주차: 압력과 봉합

- PressureGraph, Breach와 Seal
- 누출망 표시
- 봉합재 소비
- 압력 계산 자동 테스트

### 4주차: 방 변주

- 검증된 방 템플릿 제작
- 압력원, 취약 셀, 봉합 불가 셀과 표본의 제약 배치
- 진행 불가능 상태 검사

### 5주차: 정산과 저장

- 감압실 자원 사출
- 성공, 실패와 중도 정산
- SaveManager와 저장 버전 필드

### 6주차: 최소 콘텐츠

- 도구, 재질, 압력원과 보상 Resource
- 횡적 선택이 다른 접근법을 만드는지 검증

### 7주차: 밸런스와 입력 검증

- 큰 절개와 작은 절개의 비용 비교
- 봉합재, 누출량과 반동 관계 조정
- 게임패드 입력 및 접근성 검토

### 8주차: 플레이테스트와 의사결정

- 핵심 데이터 수집
- 온보딩 순서 검증
- 프레임 최적화
- 계속 개발, 핵심 규칙 재설계 또는 잔향직조 전환 결정

## 11. 검증 게이트

### 기술 검증

- 목표 하드웨어에서 프레임 예산을 지키는가?
- 절개, 반동과 봉합 판정이 동일 입력에서 재현되는가?
- 압력 그래프와 화면 표시가 일 불일치를 만들지 않는가?
- 타일 충돌 갱신이 입력 지연이나 프레임 스파이크를 만드는가?

### 재미 검증

- 플레이어가 설명 없이 절개와 반동의 관계를 이해하는가?
- 실패 후 원인을 설명하고 다음 시도에서 다른 선택을 하는가?
- 작은 절개와 반복 봉합이 지배 전략이 되는가?
- 감압실 정산 뒤 추가 탐사를 자발적으로 선택하는가?
- 절개, 추진과 봉합 중 하나가 불필요한 동사가 되지 않는가?

### 판단 원칙

- 성능 문제와 재미 문제를 분리한다.
- 임시 수치는 합격 기준이 아니라 테스트 변수로 기록한다.
- 핵심 동사 사이의 등가교환이 재미없다면 콘텐츠를 추가해 덮지 않는다.
- 기술 게이트 실패 시 먼저 그래프와 파괴 범위를 축소하고, 핵심 상호작용 자체가 실패하면 잔향직조로 전환한다.

## 12. 남은 질문

1. 절개 조작은 자유 선, 셀 선택, 방향성 도구 중 어떤 방식이 가장 읽기 쉬운가?
2. 압력 그래프의 논리 셀 크기와 시각 타일의 대응 관계는 어떻게 정의할 것인가?
3. 봉합재 제한이 자율성을 해치지 않으면서 미세 파밍을 억제할 수 있는가?
4. 적 없이도 절개, 반동과 누출만으로 첫 프로토타입이 재미있는가?
5. 감압실 정산은 한 세션에서 몇 번 제공해야 긴장과 박탈감이 균형을 이루는가?
6. 픽셀 그래픽의 파편과 압력 효과가 실제 충돌 범위를 오해하게 만들지 않는가?
7. 최신 시장 근거를 수집했을 때 절개항해의 예상 플레이어층과 가격대가 성립하는가?

이 질문에 답하기 전에는 세션 길이, 압력 임계치, 봉합재 수량, 슬로모션 시간과 반동 계수를 최종 확정하지 않는다.

# 쉬운 모델 팀 설정

계획 탭에서 팀장과 구현 담당을 선택하면 즉시 적용됩니다. 별도의 적용 버튼은 필요하지 않습니다.

- 팀장: 설계와 검토 역할을 담당합니다.
- 구현 담당: 구현과 일반 작업(custom)을 담당합니다.
- 새 작업의 기본 역할은 구현입니다.
- 각 작업 아래에 담당 모델과 작업별 직접 지정 여부가 표시됩니다.

처음 사용할 때는 로그인된 모델 중 Codex를 팀장, Antigravity를 구현 담당으로 우선 선택합니다. 해당 모델이 없으면 사용 가능한 모델을 선택합니다. 상태를 새로 확인할 때 기존 선택을 임의로 바꾸지 않습니다. 선택 모델이 사용할 수 없는 상태라면 이를 표시합니다.

## 단계별 협업 만들기

전체 목표를 입력하고 **설계 → 구현 → 검토 만들기**를 누르면 세 작업과 선행 작업·참조 관계를 생성합니다. 기존 작업이 있으면 교체 확인을 받습니다. 생성되는 작업은 현재 지정한 대상 폴더에서 실행됩니다.

팀을 고르는 것만으로 이미 작성한 작업을 자동 분할하지는 않습니다. 작업을 하나씩 직접 만들 수도 있습니다.

## 고급 설정

역할별 예외와 다른 모델로의 자동 대체는 접힌 고급 설정에서 조절합니다.

- 기본적으로 지정한 모델만 후보에 넣습니다. 사용할 수 없으면 다른 모델이 몰래 실행되는 대신 실행 불가 또는 실패로 표시됩니다.
- 자동 대체를 켜면 로그인된 다른 모델들이 후보에 추가됩니다. 화면의 화살표 순서로 후보를 확인할 수 있습니다. 실제 배정은 실행 시 가용성과 사용량 제한의 영향을 받습니다.
- 프로젝트 기본값 사용은 명시적 역할 설정을 해제합니다. 실제 기본 담당은 서버 설정에 따라 달라지므로 실행 미리보기에서 확인합니다.
- JSON에서 불러온 작업별 `providers`는 역할 설정보다 우선합니다. 작업 아래의 직접 지정 표시와 해제 버튼으로 관리합니다.
- 모든 역할에 현재 팀 적용은 작업별 직접 지정을 확인 후 해제하고 팀 설정으로 통일합니다.
- JSON 가져오기는 가져온 역할 설정을 그대로 사용합니다. 역할 설정이 없는 JSON은 프로젝트 기본값을 사용하며 이전 계획의 설정을 물려받지 않습니다.

라우팅 선택을 바꾸면 이전 실행 미리보기는 지워집니다. **실행 미리보기**를 다시 눌러 서버가 결정한 담당과 대체 후보를 확인할 수 있습니다.

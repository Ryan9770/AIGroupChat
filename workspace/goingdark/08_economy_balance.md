> 참조: `00b_core_mechanics.md`(유물 등급 가치·**세관 10% = 환전 공제**·강화 확률표·성수병 40골드),
> `07_extension_pack.md`(SQ-03 세관 5% 인하, E2 death_history), `10_pve_revision.md`(전환 내역).

| '화살' 소모품 | 상쇄 대상에 포함 | **삭제** — 플레이어에게 원거리 무기가 없음 |

| 파괴율 45% 기준 | 출처 없음 | 00b '강화 확률표'가 원본(+4 파괴 45%) |

## 1. 기준선
| 지표 | 목표 |
|---|---|
| 세션 순가치 (약탈 − 반입원가) | 평균 +80~150골드 |
| 손실 세션 비율 (PvE) | 30~45% |
| 골드 싱크/소스 비 | 0.9~1.1 (장기 균형) |

### 세관 수입 모델 (1인당/세션)
- 탈출 성공률 **65%** (PvE 코옵 기준 — v1의 55%는 PvP 사망 포함 값) ×
  성공 세션 평균 약탈 매입가 **420골드** × 공제율 **10%** = **세션당 27.3골드 싱크**
- 과세 시점: 브로카 환전 1회. 저장고 보관은 무료이며 과세 대상이 아니다.

## 2. SQ-03 영향 분석
성공 3회 누적 시 공제율 10%→5%.

| SQ-03 채택률 | 세관 수입 (세션당) | 감소분 |
|---|---|---|
| 0% | 27.3 | — |
| 30% | 23.2 | −4.1 (−15%) |
| 60% | 19.1 | −8.2 (−30%) |
| 100% | 13.7 | −13.6 (−50%) |

## 3. 상쇄 장치
| 장치 | 수치 | 발동 조건 | 예상 싱크 회복 (60% 채택) |
|---|---|---|---|
| A. 소모품 연동 가격 | 포션·붕대·램프 기름 +5% (**성수병은 40 고정 — 종단 공급가**) | SQ-03 성공 3회 달성 계정 | +2.0 |
| B. 밀수 적발료 | 은닉 실패(25%) 시 은닉 가치 15% 몰수 | SQ-03 진행 중 | +3.0 |
| C. 브로카 '장부 유지비' | 인하 상태에서 세션 시작 시 3골드 고정료 | 인하 시 항상 | +1.8 |

- **60% 채택 기준: 회복 +6.8 vs 감소 −8.2 → 상쇄율 83%.** 잔여 1.4는 채택자 소비 증가로 흡수 용인.
- 채택률 60% 초과 시 자동 발동 **장치 E**: 유지비 3→6골드 단계 인상(인하 혜택의 유지 비용이라는 서사 정당성 유지).
  E 포함 시 100% 채택에서 회복 +14.3 vs 감소 −13.6 → **상쇄율 105%**.
- 장치 D(세관 하한)는 폐기했다. 하한 16골드(8슬롯×2)가 인하 후 공제액 13골드보다 커서 **보상 자체를 무효화**했고,
  저가치 반입 세션에서는 실효세율이 기본 10%를 3배 가까이 초과해 초보 플레이어를 역차별했다.
  '저가 대량 반입 우회' 방지는 슬롯 8개 제한이 이미 수행한다.

## 4. 인플레 안전판 (누적 골드 통제)
- **보스 보상 이중 게이트(v2 신설)**: 감시자 에픽 드롭을 확정 → **45%** 로 확률화하고,
  **실시간 12시간 리스폰**을 걸었다. v1은 반복 가능한 보스가 에픽을 확정 지급해
  5층 기대가치 1,900이 세션 순가치 목표 +80~150을 12~24배 초과시켰다(04 §6 참조).
- 강화 도박: +4 파괴율을 00b 기준표의 45%에서 **55%** 로 상향 — 상위 장비 싱크.
- 에픽 '심연의 심장' 환전 상한: 브로카 매입가 시세의 70% (던전 내 사용·강화 재료 유도 — 현금화 억제).
- 저장고 이자 없음 원칙 유지 (쌓아두는 골드 = 정적, 소비 유도 설계).

### PvE 전환에 따른 소스 증가 보정
PvP 사망이 사라져 탈출 성공률이 55%→65%로 오르며 **골드 소스가 약 18% 증가**한다. 상쇄:
- 파티 플레이 시 전리품은 파티원끼리 나눠 갖는다(1인당 기대 약탈가는 인원수만큼 희석, 몹 HP 배율이 보상 배율보다 크게 설계).
- 조수 3단계 램프업으로 '한 번 더 욕심내다 전 로스트'가 v1보다 자주 발생하도록 튜닝 — 손실 세션 30~45% 하한을 지킨다.

## 5. death_history 스키마 (E2 '삼킨 왕' P2 요구)
```json
{
  "player_id": "string",
  "death_history": [
    {
      "session_id": "string",
      "floor": 1,
      "timestamp": "ISO8601",
      "loadout_hash": "string",
      "loot_snapshot": [{ "item_id": "string", "tier": "rare" }],
      "cause": "mob | tide | boss"
    }
  ]
}
```
- 저장: 세션 종료(사망) 시 서버 기록, 최근 20건 링 버퍼.
- `cause`에서 `player`(PvP 사망) 값은 PvE 전환으로 삭제.
- E2 P2 참조 규칙: 사망 층수 = 5층인 기록 우선, 없으면 임의 1건. 소환 시체 HP는 원본 로드아웃 합계 비례(최소 60, 최대 150).
- 개인정보: loadout_hash는 스냅샷 복원용 해시, 원본 아이템 ID는 서버 내부 유지.

# 12. roguelite-game 고도화 설계

> 대상: `game/` 웹 프로토타입 (Vite + Canvas2D + Web Audio, 솔로 전용)
> 작성 기준: 2026-09-14 현재 코드와 v2 기획 문서의 교차 조사

## 1. 결론

현재 빌드는 이동·근접 전투·가드·구르기·5개 층·4종 일반 적·2종 보스·시선/조수·약탈/사망 로스트·거점 경제·퀘스트·로컬 저장까지 한 세션의 골격을 갖췄다. 다만 지금의 층은 단일 직사각형 공간과 고정 콘텐츠로 구성되어 런마다 의사결정이 거의 같고, 몇몇 결함은 경제와 진행을 직접 깨뜨린다. 따라서 고도화 순서는 **정합성 복구 → 테스트 가능한 런 코어 분리 → 시드 기반 맵/빌드 변주 → 메타 진행과 콘텐츠 → UX·밸런스 출시 게이트**로 고정한다.

이번 범위의 완성 정의는 “30분 이내에 한 판을 끝낼 수 있고, 동일 시드에서는 재현되며, 매 런 다른 경로와 빌드 선택이 생기고, 탈출/사망 결과가 저장과 경제에 정확히 한 번 반영되는 솔로 PvE 버티컬 슬라이스”다. 듀오/트리오 코옵, 7막 전체, 엔딩 5종, 라이브 서비스, 서버 권위 세이브는 별도 기술 기획 없이는 포함하지 않는다.

### 2.2 이미 플레이 가능한 핵심

- 플레이어: WASD, 전력질주/스태미나, 가드, 구르기 무적, 근접 공격, 등불, 소모품 단축키.
- 런: 1~5층 순차 진입, 상자/제단, 8슬롯 인벤토리, 일반 적 리스폰, 시선 4구간, 22/27/30분 조수, 18분 게이트.
- 콘텐츠: 해골병정/병장, 심연충, 골렘, 왕실 호위, 감시자, 하르트, 메인 1개와 사이드 1개 의뢰.
- 메타: 골드, 상점, 환전 10%, 무기 +0~+5 강화, 저장고, 사망 기록 20건, 로컬 세이브.
- 표현: Canvas2D 도형 렌더, DOM HUD/패널, Web Audio 합성 효과음.

## 3. 고도화 구현 범위

### 3.1 기반 계층: 결정론적 런 코어

`DungeonScene`에서 아래 순수 규칙을 분리한다.

- `RunState`: 시드, 규칙 버전, 층/방, 시간, 플레이어 런 상태, 드롭, 종료 상태.
- `RunEngine.step(input, dt)`: 고정 스텝(권장 1/60초)으로 이동·공격·AI·타이머·종료 판정 수행.
- `SeededRng`: 이름 있는 스트림(`map`, `spawn`, `loot`, `combat`)을 제공해 한 영역의 변경이 다른 난수를 흔들지 않게 함.
- `CollisionWorld`: 벽/문/원/부채꼴/투사체 충돌과 LOS 판정.
- `RunSettlement`: `in_run → extracted/dead → committed` 단방향 상태 머신. 같은 결과를 두 번 제출해도 저장 변화가 한 번만 일어나는 멱등 정산.
- `Renderer`와 `InputController`: 엔진 스냅샷만 읽고 규칙을 변경하지 않음.
- `SaveRepository`: `saveVersion`, 마이그레이션, 유효성 검사, 가져오기/내보내기, 손상 백업.

완전한 ECS 도입은 현재 규모에 과하다. 기존 클래스형 엔티티를 유지하되 시간·랜덤·저장·UI 의존성을 생성자 인자로 주입하는 수준으로 경계를 세운다.

### 3.2 로그라이트 런 변주

1. **방 그래프형 층 생성**
   - 층마다 6~10개 방: 시작, 전투, 엘리트, 보물, 제단/상인, 이벤트, 계단, 탈출 게이트(1·3·5층 체크포인트 및 5층 보스 처치 게이트, 2~5층 역주행 계단).
   - 시작에서 목표와 탈출로 가는 경로가 항상 연결되고, 보상 높은 가지일수록 전투/시선 비용이 커진다.
   - 같은 `seed + rulesVersion`은 방 그래프, 스폰, 상자 결과가 동일하다.
   - 맵 생성 실패 시 제한 횟수 재시도 후 검증된 안전 템플릿으로 폴백한다.

2. **런 내 빌드 선택**
   - 전투/엘리트 완료 시 경험 또는 “기억 파편”을 얻고, 임계치마다 3개 중 1개 축복을 선택한다.
   - 첫 버전은 18개 축복을 세 계열로 제공한다: 집행(공격/콤보), 생존(가드/회피/회복), 등불(시선/소음/탐지).
   - 축복은 등급, 최대 중첩, 태그, 수치, 적용 훅을 데이터로 선언한다. 한 런에서 6~9회 선택을 목표로 한다.
   - “무조건 좋은 수치 증가”만 두지 않고 최소 6개는 명확한 대가를 가진다(예: 피해 증가 대신 시선 상승).

3. **리스크/리턴 선택 강화**
   - 1·3·5층 체크포인트에서 탈출 선택을 보장하고, 심층 진행 시 희귀도와 위협이 함께 증가한다.
   - 상자 열기, 큰 소음, 엘리트 처치가 시선/추격 감독자(Director)의 예산을 올린다.
   - 보스 처치 보상은 바닥 보상 선택 화면으로 전달하여 가방 초과 시 버리기/교체를 직접 결정한다.
   - 런 결과에 도달 층, 방 수, 빌드, 획득/유실 가치, 피해 원인, 시드, 플레이 시간을 기록한다.

4. **콘텐츠 팩**
   - 기존 4종의 역할을 먼저 명료화한 뒤 신규 일반 적 2종과 엘리트 변형 3종을 추가한다.
   - 방 이벤트 8종, 상자 변형 3종, 저주 유물 8종, 축복 18종을 첫 고도화 상한으로 둔다.
   - 감시자와 하르트는 공격 형상을 시각적으로 예고하고, 보스 방 진입 시 문 잠금/처치 후 해제 상태를 명시한다.

### 3.3 메타 진행

- 영구 강화는 순수 공격력 누적보다 **새 선택지 해금** 중심으로 제한한다: 시작 축복 후보, 이벤트, 유물, 소비 아이템.
- 무기 강화는 기존 +0~+5를 유지하되 비용과 파괴 결과를 데이터화하고 경제 시뮬레이션으로 검증한다.
- 의뢰는 `조건 → 진행 이벤트 → 보상 → 완료` 데이터 구조로 옮기고 현재 두 의뢰를 마이그레이션한다.
- 첫 릴리스는 계정 레벨 10, 해금 노드 12개, 튜토리얼 의뢰 3개까지로 제한한다.
- 콘텐츠 해금과 전투 파워 격차를 분리해 신규 플레이어가 보스 공략에 필수 영구 수치를 요구받지 않게 한다.

### 3.4 UX·접근성·운영 도구

- 최초 5분 온보딩: 이동/공격/가드/구르기/약탈/탈출을 실제 행동으로 확인하는 단계형 안내.
- 일시정지, 키 재지정, 게임패드, 마스터/효과음 볼륨, 화면 흔들림·깜빡임 감소, 색 외 시선 구간 표기.
- 1280×720 기준 화면을 유지하되 1024×576~1920×1080에서 비율 보존 스케일링과 패널 스크롤을 보장한다.
- 개발 모드에서 시드 입력, 시간 배속, 층 이동, 무적, 아이템 지급, 이벤트 로그 내보내기를 제공하되 프로덕션 UI에서는 숨긴다.
- 개인 식별 정보 없이 런 요약 JSON을 로컬로 내보내 밸런스 집계에 사용할 수 있게 한다.

|---|---:|---|---|

## 5. 검증 전략과 수용 기준

### G0. 빌드·정적 품질

- 깨끗한 설치에서 `npm ci && npm run build && npm test && npm run lint`가 모두 종료 코드 0.
- `game/src`의 문법 오류, 미사용 치명 경로, 브라우저 콘솔 error/unhandled rejection 0건.
- UI 문자열에서 `�` 또는 알려진 모지바케 패턴 0건; HTML과 JS 모두 UTF-8.
- 현재 조사 환경에서는 `node --check`가 모든 JS 파일에 통과했다. `npm run build`는 샌드박스가 상위 디렉터리 열람을 거부해 Vite 설정 로딩이 실패했으므로, 일반 개발 환경/CI에서 재검증해야 한다.

### G1. 핵심 규칙 회귀 테스트

- 상점의 네 소모품 각각을 구매→던전 사용했을 때 골드/슬롯이 1회 감소하고 정의된 효과가 정확히 적용된다.
- 가치 100G 약탈품을 탈출해도 골드는 변하지 않고 아이템은 보존된다. 허브 환전 시에만 10G 공제·90G 지급·아이템 제거가 일어나며 재환전은 불가능하다.
- 피격 중 게이트 충전은 0으로 돌아가고, 연속 무피격 8초에만 정산된다. 종료 콜백을 두 번 호출해도 통계·골드·아이템 변화는 한 번뿐이다.
- 1~5층의 모든 시작 상태에서 유효한 탈출 경로가 존재한다. 4·5층 진입이 강제 사망 상태를 만들지 않는다.
- 감시자 파동의 감속은 시뮬레이션 시간 3.0초 동안만 적용되고 이후 기본 속도로 돌아온다.
- 사망 시 런 인벤토리는 비워지고 `runs/deaths/deathStreak/deathHistory`는 1회 증가하며, 저장고와 이미 영구 보유한 해금은 손실되지 않는다.
- 가방 초과 아이템은 자동 소멸하거나 성공으로 표시되지 않고, 바닥에 남거나 교체 UI로 전달된다.

### G2. 결정론·맵 속성 테스트

- 동일한 `seed`, `rulesVersion`, 입력 프레임은 10회 실행에서 최종 상태 해시가 같다.
- RNG 스트림 분리 테스트: 장식용 난수 호출을 추가해도 맵/드롭/전투 결과는 변하지 않는다.
- 10,000개 생성 시드 모두 시작→계단/보스와 시작→탈출 경로가 존재하고, 방/문이 겹치거나 월드 경계를 벗어나지 않는다.
- 각 층에 전투방 1개 이상, 보물방 1개 이상, 1·3·5층 체크포인트 게이트 및 2~5층 역주행 계단이 보장되며 보스는 시작방 최단 BFS 거리 ≥ 3을 만족한다.
- 안전 템플릿 폴백률 0.1% 미만; 초과하면 생성 알고리즘 결함으로 출시를 막는다.

### G3. 전투·빌드·밸런스

- 각 공격의 텔레그래프 렌더 영역과 실제 피격 영역 차이가 월드 좌표 0.15m 이내다.
- 가드 70%, 왕실 호위 감소 40%, 골렘 방어 15%, 구르기 무적 0.3초를 고정 시드 단위 테스트로 확인한다.
- 일반 난도 봇/플레이테스트 기준: 1층 첫 사망 중앙값 5분 초과, 전체 성공률 55~75%, 감시자 도달률 25~45%, 손실 세션 30~45%.
- 성공 세션 순가치 평균 +80~150G, 장기 골드 싱크/소스 비 0.9~1.1. 10,000회 몬테카를로 결과와 최소 30회 인간 플레이 결과를 함께 본다.
- 집행/생존/등불 각 계열을 주축으로 한 빌드가 동일 난도 감시자를 처치할 수 있고, 단일 축복 선택률이 70%를 넘으면 재조정한다.
- 1× 실시간 기준 한 런 중앙값 20~28분, 90백분위 30분 이하. 개발 배속 결과는 밸런스 표본에서 제외한다.

### G4. 세이브·호환성·복구

- 빈 저장, 현행 v1 저장, 필드 일부 누락 저장, 손상 JSON을 각각 로드해 크래시 없이 v2 기본 상태를 만든다.
- 마이그레이션 전 원문 백업을 남기며 gold, inventory, storage, weaponLevel, quests, factionRep, stats, deathHistory가 보존된다.
- 새 게임/탈출/사망/구매/환전/강화/의뢰 완료 직후 새로고침해 동일 상태가 복구된다.
- 저장 쓰기 실패 시 런 결과가 성공으로 표시되지 않고 재시도 또는 내보내기 안내를 제공한다.

### G5. E2E·성능·접근성

- Playwright 시나리오: 첫 실행→튜토리얼→상점 구매→고정 시드 런→탈출→환전→강화→새로고침, 그리고 별도 사망/퀘스트/보스 경로.
- 기준 PC의 1280×720, 일반 전투 30개 엔티티에서 프레임 시간 p95 16.7ms 이하, 100개 스트레스에서 p95 33.3ms 이하; 30분 런의 지속 메모리 증가 20MB 이하.
- 키보드만으로 허브의 모든 기능과 설정을 조작할 수 있고 포커스가 보인다. 게임패드로 이동·전투·상호작용·메뉴가 완주 가능하다.
- 1024×576, 1280×720, 1920×1080에서 HUD 겹침/화면 밖 필수 버튼 0건. 200% 텍스트 확대에서 패널 스크롤 가능.
- 화면 흔들림/깜빡임 감소를 켜면 반복 플래시가 사라지고, 시선 위험은 색 외 숫자·라벨·패턴으로도 구분된다.

## 6. 테스트 구성 제안

- 단위: Vitest — 인벤토리, 경제 정산, 상태 효과, RNG, 데이터 유효성, 세이브 마이그레이션.
- 속성 기반: 생성기 불변식과 아이템/정산 보존 법칙. 필요하면 `fast-check`를 추가한다.
- 시뮬레이션: 렌더 없는 `RunEngine`으로 10,000회 맵/경제/드롭 통계 생성, JSON과 Markdown 요약 출력.
- 통합: 고정 시드 엔진 스냅샷과 보스 페이즈 전환/AI 상태 머신 테스트.
- E2E: Playwright — 브라우저 입력, HUD, 저장, 결과 화면, 새로고침 복구.
- 시각 회귀: 허브, 각 시선 구간, 인벤토리, 축복 3택, 보스 텔레그래프, 결과 화면을 3개 해상도로 캡처 비교.

CI 최소 행렬은 Node LTS 1종과 Chromium 최신 1종으로 시작한다. 결정론 스냅샷과 1,000시드 속성 테스트는 모든 PR에서, 10,000회 시뮬레이션과 장시간 메모리 테스트는 야간 실행으로 분리한다.

## 7. 구현 전 결정해야 할 정책

다음은 코드를 늘리기 전에 명시적으로 확정해야 한다.

1. **아이템 소유권:** 기획 원본에 맞춰 “탈출=영구 보유, 허브 환전=골드화”로 확정한다. 결과 화면의 기존 즉시 지급 표시는 회수 가치로 바꾼다.
2. **심층 귀환:** 1·3·5층 체크포인트 게이트 + 2~5층 역주행 계단 복합 정책으로 확정한다. 1·3·5층에는 전용 탈출 게이트 방이 배치되고, 2~5층 시작방에는 이전 층 복귀 계단이 제공되며, 5층 감시자 보스 처치 시 승리 탈출 게이트가 생성된다.
3. **실시간 12시간 보스 리스폰:** 솔로 오프라인 프로토타입에서는 기기 시계 조작과 테스트성을 해친다. 첫 릴리스에서는 런당 1회로 바꾸고 서버 운영 단계에서 재검토한다.
4. **영구 성장 철학:** 수직 공격력 누적 상한과 해금 중심 진행 비율을 정한다. 권장안은 영구 전투력 +15% 상한, 나머지는 선택지 해금이다.
5. **개발 배속:** 현재 3×/6×는 전투까지 가속해 실제 난도와 다른 결과를 만든다. 테스트 전용 표시를 강화하고 공식 지표에서는 제외한다.

## 8. 완료 정의

고도화 작업은 기능 개수로 완료 처리하지 않는다. 단계별 자동 테스트가 있고, G0~G5를 모두 통과하며, 알려진 P0/P1 결함이 0건이고, 고정 시드 실행으로 버그를 재현할 수 있으며, 30회 이상 실제 플레이 표본이 목표 세션 길이와 경제 범위 안에 들어왔을 때 버티컬 슬라이스를 완료로 판정한다.

# 13. roguelite-game 고도화 구현 검토

> 검토 대상: `12_roguelite_enhancement_plan.md`와 `game/` 구현
> 검토일: 2026-09-14

## 1. 결론

**판정: 완료 불가(보완 후 재검토).** 기존 설계에서 P0로 지정한 소모품 데이터 보존, 탈출 시 즉시 환전 제거, 4·5층 귀환 경로, 3초 감속 복원은 코드에 반영됐다. 시드 RNG, 방 그래프, 18개 축복, 정산 상태 머신, v2 세이브와 22개 자동 테스트도 추가됐다.

그러나 설계의 완료 정의는 G0~G5 전체 통과와 알려진 P0/P1 0건이다. 현재는 결정론적 런 코어, 맵 충돌/LOS, 맵 생성 불변식, 저장 실패 처리, 콘텐츠/메타 상한, E2E·성능·접근성 검증이 미완료다. 또한 역주행으로 층을 다시 불러올 때 상자·적·보스가 초기화되어 무한 파밍이 가능한 신규 경제 결함이 있다. 따라서 “핵심 런 코어와 버티컬 슬라이스 검증 완료”라는 구현 결과 요약은 실제 수용 기준보다 넓게 주장한다.

## 2. 주요 발견 사항

### [높음] R1. 역주행이 층 상태를 초기화해 무한 전리품·XP 파밍을 허용한다

- `DungeonScene._descend()`와 `_ascend()`는 모두 `_loadFloor()`를 호출한다(`game/src/scenes/dungeon.js:524-535`).
- `_loadFloor()`는 매번 새 방 그래프를 만들고, 적·상자·제단·바닥 아이템·보스를 모두 초기화한 뒤 다시 배치한다(`game/src/scenes/dungeon.js:103-248`).
- 하강할 때마다 60 런 XP도 다시 지급한다(`game/src/scenes/dungeon.js:524-528`).
- 결과적으로 1↔2층을 반복하면 상자와 적을 재생성하고 축복 XP를 반복 획득할 수 있다. 4층 하르트와 퀘스트 드롭도 재생성 대상이다. 이는 새 P0급 경제/진행 악용이며, 동일 런의 방문 완료 상태 보존 요구와 충돌한다.
- 층별 그래프와 엔티티/상자/제단/보스 완료 상태를 런 상태에 캐시하고, 최초 전진 보상은 층마다 한 번만 지급해야 한다.

### [높음] R2. “결정론적 런 코어”가 구현되지 않았다

- `SeededRng` 자체와 일부 스폰·전리품·플레이어 피해 굴림은 시드화됐다.
- 하지만 골렘 공격 선택은 `Math.random()`을 직접 사용하고(`game/src/entities/enemies.js:208`), 감시자 3페이즈 공격 선택도 `Math.random()`을 직접 사용한다(`game/src/entities/boss.js:108`). 같은 시드·입력으로도 전투 결과가 달라질 수 있다.
- `RunState`, `RunEngine.step`, `rulesVersion`, 고정 1/60초 스텝과 최종 상태 해시가 없다. 앱은 가변 RAF `dt`를 그대로 장면에 전달한다(`game/src/main.js:68-73`, `game/src/scenes/dungeon.js:999-1006`).
- 기존 RNG 테스트는 생성기 시퀀스와 스트림 독립성만 확인할 뿐, 설계 G2의 “동일 시드·규칙 버전·입력 프레임 10회 최종 상태 해시 동일”을 실행하지 않는다.

### [높음] R3. 저장 실패가 발생해도 성공 결과와 경제 변경을 그대로 표시한다

- `saveState()`는 쓰기 실패 시 `false`를 반환한다(`game/src/systems/save.js:147-158`).
- 결과 화면은 반환값을 확인하지 않고 즉시 탈출/사망 성공 화면을 표시한다(`game/src/main.js:36-58`). 구매·환전·강화·해금·퀘스트 완료도 모두 저장 결과를 무시한다(`game/src/scenes/hub.js:141`, `160`, `233`, `250`, `260-304`).
- localStorage 용량 초과나 브라우저 저장 차단 시 현재 탭의 메모리만 변경되고, 새로고침하면 결과가 사라진다. 이는 G4의 “저장 쓰기 실패 시 성공으로 표시하지 않고 재시도 또는 내보내기 안내”를 직접 위반한다.
- 정산 커밋은 저장 성공 뒤 확정하고, 실패 시 결과 모달 대신 재시도/JSON 내보내기 경로를 제공해야 한다.

### [높음] R4. 10,000시드 테스트가 G2 불변식을 충분히 검사하지 않아 결함을 통과시킨다

별도 검증에서 시드 `100000..109999`, 층을 1~5로 순환해 생성한 10,000개 그래프를 설계 조건으로 재검사했다.

| 검사 | 위반 건수 | 근거 |
|---|---:|---|
| 보물방 1개 이상 | 735 | 역할 배정이 잎 노드가 있을 때만 보물방을 만든다(`roomGraph.js:148-155`). |
| 층당 탈출 후보 2개 | 10,000 | 체크포인트 층에 단일 게이트만 배정하고 2·4층은 게이트가 없다(`roomGraph.js:138-146`). |
| 보스가 시작방 최단 경로에 바로 붙지 않음 | 41 | 역할 배정 뒤 추가 간선으로 생긴 실제 최단 경로 제약을 검사하지 않는다. |
| 생성 그래프 `worldW/worldH` 유효 | 10,000 | 일반 생성 결과는 두 필드를 0으로 반환한다(`roomGraph.js:115-123`). 장면이 재계산해 현재 화면은 동작하지만 그래프 데이터 계약은 잘못됐다. |

폴백은 0건, 전투방 누락도 0건이었다. 기존 테스트는 생성기의 자체 `validateGraph()`를 다시 호출하는데(`game/test/roomGraph.test.js:26-28`), 이 검증기는 연결성·단일 목표·체크포인트 단일 게이트·격자 좌표 중복만 검사한다(`game/src/core/roomGraph.js:187-228`). 따라서 테스트 이름의 “valid”가 설계 G2 전체 충족을 의미하지 않는다.

### [중간] R5. 18개 축복 중 최소 2개는 전투 효과가 없다

- `출혈상`은 공격 시 적 객체에 `bleedDps/bleedTimer`를 기록한다(`game/src/scenes/dungeon.js:389-392`).
- `눈부신 섬광`은 적 객체에 `stunTimer`를 기록한다(`game/src/scenes/dungeon.js:356-360`).
- 그러나 적 업데이트 코드 어디에서도 `bleedDps`, `bleedTimer`, `stunTimer`를 읽거나 감소시키지 않는다. 따라서 지속 피해와 2초 경직이 발생하지 않는다.
- 축복 테스트는 총 개수/분류/서로 다른 3택과 `묵직한 일격`, `철벽 방진`의 필드 변경만 검사한다(`game/test/blessings.test.js:7-49`). 18개 축복의 런타임 효과를 검증하지 않는다.

### [중간] R6. 방 그래프는 시각화됐지만 충돌·문·LOS가 구현되지 않았다

- 방과 벽은 Canvas 선으로만 그린다(`game/src/scenes/dungeon.js:1092-1127`).
- 플레이어와 적은 전체 월드 사각형에만 clamp된다(`game/src/scenes/dungeon.js:1017-1018`, `1047-1049`). 벽/문 충돌과 원거리 LOS 판정 모듈은 없다.
- 따라서 설계 단계 2의 `CollisionWorld`, 문/벽/LOS, 텔레그래프와 실제 히트 영역 정합성은 미충족이며, 기존 P1이 해소되지 않았다.

### [중간] R7. 단계 4~5 범위와 G3 밸런스 증거가 없다

- 메타 해금은 8개다(`game/src/scenes/hub.js:22-31`). 설계 상한은 12개 해금 노드와 튜토리얼 의뢰 3개다.
- 신규 일반 적 2종, 엘리트 변형 3종, 방 이벤트 8종, 저주 유물 8종, 상자 변형 3종이 추가되지 않았다. `ENEMY_DEFS`는 기존 5개 정의를 유지한다(`game/src/data/data.js:58-98`).
- 온보딩, 일시정지, 키 재지정, 게임패드, 볼륨/화면 흔들림/깜빡임 설정 UI, 런 요약 내보내기가 없다. 허브의 클릭 대상은 `div`/`span`이며 `button`, `tabindex`, 키보드 활성화 처리가 없어 키보드 전용 완주 조건을 충족하지 않는다(`game/src/scenes/hub.js:343-381`).
- 봇/인간 플레이 표본, 10,000회 경제 몬테카를로, 30분 세션 성능/메모리, 3해상도·200% 텍스트 검증 결과가 없다.

### [낮음] R8. 환전 감면 해금 후 결과 화면 예상액이 실제 환전액과 다르다

- 허브 환전은 `customs_favor` 해금 시 8%를 적용한다(`game/src/scenes/hub.js:152-156`).
- 런 정산과 결과 화면은 항상 기본 10%로 계산·표시한다(`game/src/core/settlement.js:33-35`, `game/src/main.js:43-45`).
- 실제 지급과 결과 요약의 예상 지급액이 일치하도록 동일 정책 함수를 사용해야 한다.

## 4. 테스트 재실행 결과

- 격리 환경 `npm ci --prefer-offline --no-audit --no-fund`: 성공, 11개 패키지 설치.
- `npm test`: **22/22 통과**, 8 suites, 실패/스킵 0.
- `npm run lint`: 성공. 실제 내용은 ESLint가 아니라 `game/src`의 JS 15개에 대한 `node --check`다.
- `npm run build`: 실패. Vite/esbuild 설정 로더가 샌드박스 상위 디렉터리를 읽지 못한 환경 오류(`Cannot read directory ... Access is denied`).
- 보조 Vite 빌드(`configFile:false`, 실제 설정과 같은 `base:'./'`): 성공, 18 modules transformed, JS 87.80 kB, CSS 2.97 kB.
- headless Chrome 초기 로드: 허브 DOM과 한글 UI가 정상 생성됐고 stderr 출력 없음.
- 보조 10,000시드 속성 검사: 폴백 0, 전투방 누락 0, 보물방 누락 735, 탈출 후보 2개 미만 10,000, 보스-시작 직접 연결 41, 그래프 월드 크기 0 반환 10,000.

기존 22개 테스트의 통과는 회귀의 일부만 증명한다. 특히 경제 테스트는 `HubScene.buyItem/sellItem`을 호출하지 않고 객체 생성과 환전 산식을 테스트 안에서 복제하며(`game/test/economy.test.js:24-57`, `85-106`), 탈출 경로 테스트는 2~5층에 시작방이 있다는 사실만으로 복귀 계단을 간주한다(`game/test/escape_path.test.js:20-24`). 통합 결함을 잡기 위해 실제 장면 메서드 또는 분리된 도메인 서비스를 직접 호출하도록 바꿔야 한다.

## 5. 재검토 전 최소 조치

1. 층 상태를 런 동안 영속화하고 역주행 재생성/반복 XP 지급을 막는 회귀 테스트를 추가한다.
2. 모든 게임 랜덤과 시간을 `RunEngine`에 주입하고 `rulesVersion` 및 고정 스텝 상태 해시 테스트를 구현한다.
3. 그래프 검증기를 G2 전체 불변식으로 확장하고 현재 확인된 보물방/탈출 후보/보스 인접 위반을 수정한다.
4. 출혈·경직 상태 효과를 적 업데이트에 연결하고 18개 축복별 실제 효과 테스트를 추가한다.
5. 저장 성공을 정산 커밋의 전제조건으로 만들고 실패 재시도/내보내기 UI를 제공한다.
6. 충돌/문/LOS를 구현한 뒤 단계 4~5 콘텐츠, Playwright E2E, 성능·접근성·30회 플레이 표본을 채운다.

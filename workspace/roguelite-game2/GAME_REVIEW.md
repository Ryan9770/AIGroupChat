# Dungeon of the Abyss 구현 리뷰

검토일: 2026-09-16  
대상: `roguelite-game/index.html`, `style.css`, `sprites.js`, `game.js`  
판정: **조건부 합격 — 데스크톱 MVP는 플레이 가능하지만, 모바일·전투 규칙·아이템 효과의 핵심 결함 때문에 출시 준비 상태는 아님**

## 1. 요약

이 구현은 단순 프로토타입을 넘어 절차 생성 맵, FOV, 턴제 전투, 3개 직업, 5개 층, 상점, 비밀방/미믹, 유물 세트, 영구 성장, 합성 BGM, 승리·패배 루프까지 한 번에 연결한 완성도 높은 데스크톱 데모다. 실제 Chrome 부팅에서 페이지 예외 없이 게임 객체와 ROT.js가 초기화됐고, 전투 보상·상점 결제·계단 이동·게임 오버·승리 전환도 동작했다. 비주얼 톤과 정보 밀도도 일관적이다.

반면 모바일은 핵심 UI가 잘리고 스킬을 사용할 수 없으며, 일부 아이템과 장비 효과가 실제로 적용되지 않는다. 상태효과 처리 순서 때문에 `1턴 기절`은 실질적으로 적 행동을 막지 못하고 `2턴 회피/빙결`도 한 턴만 유효하다. 현재 상태는 “데스크톱에서 기능을 시연할 수 있는 MVP”로는 좋지만, 플레이어에게 약속한 규칙이 일관되게 지켜지는 제품 빌드로 보기는 어렵다.

## 3. 잘된 점

- 코어 루프가 끊기지 않는다. 새 런 → 탐색/전투 → 층 이동 → 승리/패배 → 영구 성장의 흐름이 한 빌드 안에 연결돼 있다.
- 데스크톱 정보 설계가 좋다. 체력·마나·장비·스킬·미니맵·전투 로그가 동시에 보이면서도 화면의 중심은 캔버스에 남는다.
- 클래스별 플레이 감각이 구분된다. 워리어의 방어/광역, 도적의 치명타/회피, 마법사의 원거리/제어가 데이터와 스킬 분기로 표현돼 있다.
- `localStorage` 저장 데이터에 버전 키와 구버전 fallback이 있고, 상점은 검증 후 차감/판매 완료를 한 번만 커밋한다.
- B2F/B4F 상인, B3F/B5F 보스, 비밀방·상자·미믹, 유물 2세트 등 콘텐츠 레이어가 서로 연결돼 반복 플레이의 재료가 충분하다.
- 픽셀 스프라이트, 룬, 금색/청록색 강조, 화면 효과, 합성 오디오가 동일한 다크 판타지 방향을 유지한다.

## 4. 우선순위별 결함

### P1 — 다음 플레이테스트 전에 수정

#### 4.1 모바일에서 핵심 게임 정보와 스킬이 사라짐

- `style.css:191`에서 860px 이하일 때 왼쪽 사이드바 전체를 숨긴다. 이 안에 HP, MP, 상태효과, 장비와 1~4 스킬 버튼이 모두 있다.
- 모바일 터치 UI에는 이동, 대기, 가방, 계단만 있고 스킬 1~4 버튼이 없다. 물리 키보드가 없는 기기에서는 클래스 핵심 능력을 사용할 수 없다.
- 390px 뷰포트에서 실제 문서 폭이 722px였다. 헤더의 `header-meta`와 하단 액션 영역에 모바일 재배치 규칙이 없어 오른쪽 정보가 화면 밖으로 잘린다. `body { overflow-x: hidden; }` 때문에 사용자가 잘린 영역으로 스크롤할 수도 없다.

개선: 모바일 전용 `compact-vitals`와 4칸 스킬바를 캔버스 아래에 추가하고, 헤더는 2행 또는 축약 메뉴로 재배치한다. 320/390/768/1024px 회귀 테스트에서 `scrollWidth <= innerWidth`를 자동 검증한다.

#### 4.2 상태효과 지속 턴이 설명보다 짧음

- 강타는 적에게 `stun = 1`을 부여한다(`game.js:2565`). 그러나 `endTurn()`은 적 행동 전에 `processMonsterStatusEffects()`를 호출하고, 여기서 stun/freeze를 먼저 1 감소시킨다(`game.js:2301-2302`). 결과적으로 1턴 기절은 0이 된 뒤 적이 즉시 행동한다.
- 같은 이유로 눈보라의 `freeze = 2`(`game.js:2702`)는 적 행동을 한 번만 막는다.
- 연막의 `dodge = 2`(`game.js:2660`)도 플레이어 효과를 적 행동 전에 감소시키므로 실질적으로 한 턴만 완전 회피한다.
- 공격력 버프도 같은 순서로 감소해 표기 턴수보다 플레이어 행동 1회가 적다.

개선: “행동 차단 판정 → 해당 개체 행동 생략 → 턴 종료 시 duration 감소” 순서로 통일하거나, 효과에 `appliedOnTurn`을 저장해 부여 직후의 감소를 건너뛴다. 1/2/3턴 경계값 테스트를 추가한다.

#### 4.3 판매되는 물약 두 종이 효과 없이 소모됨

- `invisibility_pot`과 `invulnerability_pot`은 카탈로그와 상점에 존재한다(`game.js:963-964`).
- `useItem()`의 potion 분기는 HP, MP, cleanse만 처리하며 invisibility/invulnerable을 상태에 적용하지 않는다(`game.js:2750` 부근).
- 몬스터 감지와 `damagePlayer()`에도 두 상태를 해석하는 분기가 없다. 현재는 구매·사용·턴 소비 후 아무 전투 효과가 없다.

개선: 상태 필드, HUD 배지, 턴 감소, AI 감지, 직접 피해·함정·지속 피해의 무적 정책을 함께 구현한다. 당장 구현하지 않을 경우 두 아이템을 상점 풀에서 제거해야 한다.

#### 4.4 장비의 최대 마나 옵션이 반영되지 않음

- 마법사의 시작 무기/방어구는 각각 `maxMp +20`, `maxMp +15`를 표기하고, 마나 반지도 `maxMp +25`를 표기한다(`game.js:945-946`, `986`).
- 플레이어의 `maxMp`는 클래스 기본값으로만 초기화되고(`game.js:1724-1726`), 파생 스탯 함수는 HP/ATK/DEF/CRIT만 있으며 MP 계산 함수가 없다(`game.js:2904-2931`).
- 장비 교체 시 HP 상한만 보정하며 MP 상한은 다시 계산하지 않는다.

개선: `baseMaxMp`와 장비 옵션을 합산하는 `getTotalMaxMp()`를 추가하고 HUD, 회복, 장착/해제, 레벨업이 모두 이를 사용하게 한다. 마법사 시작 MP의 기대값도 명세로 고정한다.

#### 4.5 상인 보스가 최종 보스 전용 AI와 대사를 상속함

- `shop_guard`는 `isBoss: true`다(`game.js:859` 부근).
- `monsterTurn()`의 `if (monster.isBoss)` 분기는 타입을 구분하지 않고 섀도우 드레이크 전용 분노 대사, 브레스, 해츨링 소환을 실행한다(`game.js:2317` 부근).
- 처치 시 승리만 별도 예외 처리했기 때문에, 전투 중에는 상인이 섀도우 드레이크처럼 행동하고 이름이 맞지 않는 대사가 노출될 수 있다.

개선: `isBoss`는 HUD/보상 분류에만 쓰고, 행동은 `aiProfile: 'shadow_drake' | 'merchant_guard'` 같은 명시적 전략으로 분리한다.

### P2 — 첫 공개 빌드 전에 수정

#### 4.6 엔티티와 아이템 좌표가 겹침

- 몬스터를 먼저 배치한 뒤 아이템을 배치하지만(`game.js:1825-1873`), `DungeonFloor.isTileReserved()`는 게임 객체의 `monsters`/`itemsOnFloor`를 알지 못한다.
- 실제 100개 층 표본 중 30개 층에서 몬스터-아이템 등을 포함한 좌표 중복이 35건 발생했다.

개선: 공통 `occupancy` 집합을 생성 단계 전체에 전달하거나 `RogueliteGame.isPositionFree()` 하나로 계단·제단·상자·상인·몬스터·아이템을 모두 검사한다.

#### 4.7 “안전한 방” 순간이동이 안전을 검사하지 않음

- 마법사 왜곡과 전위 스크롤은 무작위 방의 중심 좌표로 플레이어를 바로 옮긴다(`game.js:2708`, `2803`).
- 해당 좌표의 몬스터, 상인, 상자, 함정 점유 여부를 검사하지 않는다. 설명과 달리 적과 같은 타일에 겹치거나 즉시 위험에 빠질 수 있다.

개선: 도달 가능하고 비점유이며 함정이 없고 적과 최소 거리를 만족하는 후보를 찾아 이동한다. 후보가 없으면 MP/아이템을 소비하지 않는다.

#### 4.8 모달 접근성 상태가 실제 표시 상태와 반대

- 모든 모달은 HTML에서 `aria-hidden="true"`로 시작하지만, `openModal()`/`closeModal()`은 CSS 클래스만 바꾸고 ARIA 값을 갱신하지 않는다(`game.js:3709-3719`). 활성 모달도 보조기술에는 숨겨진다.
- 포커스 이동/복원과 포커스 트랩이 없고, Tab 입력은 뒤쪽 게임 UI로 빠질 수 있다.
- viewport가 `maximum-scale=1.0, user-scalable=no`라 확대가 차단된다(`index.html:5`).

개선: `role="dialog"`, `aria-modal="true"`, 동적 `aria-hidden`, 첫 초점·포커스 복원·Tab trap을 적용하고 사용자 확대 제한을 제거한다.

#### 4.9 핵심 진행 목표를 건너뛸 수 있음

- 계단 하강은 현재 타일만 검사하며 해당 층의 보스, 비석, 핵심 이벤트 완료를 요구하지 않는다.
- B3F 데스 나이트와 대부분의 성장 콘텐츠를 건너뛰고 B5F까지 달리는 것이 가능해, 설계한 콘텐츠와 밸런스 곡선을 우회한다.

개선: 의도한 것이 자유로운 위험 감수라면 UI로 명시하고 보상을 조정한다. 아니라면 보스/룬/열쇠 조건 중 하나를 계단에 연결한다.

### P3 — 유지보수와 제품 안정성

- `game.js`가 약 4,500줄의 전역 클래스/상수와 DOM 제어를 한 파일에 담고 있어 회귀 범위가 크다. 데이터, 생성, 전투 규칙, 저장, UI, 오디오를 모듈로 분리해야 한다.
- 실행 가능한 자동 테스트와 패키지/의존성 잠금 파일이 없다. 이번에 발견한 턴 경계·장비 파생 스탯·좌표 배타성은 단위 테스트로 잡기 쉬운 문제다.
- ROT.js를 `@2` CDN URL 하나에 의존해 네트워크 장애와 상위 버전 변경의 영향을 받는다. 정확한 버전 고정과 로컬 vendor 또는 SRI fallback이 필요하다.
- 재현 가능한 seed가 없어 생성 버그나 밸런스 제보를 동일한 맵으로 재실행하기 어렵다. run seed를 저장하고 결과 화면에 노출하는 편이 좋다.
- 영구 업그레이드는 상한이나 체감 감소가 없어 장기적으로 난이도를 완전히 무력화할 수 있다. 최대 레벨, 비용 곡선, 또는 난이도 스케일을 함께 설계해야 한다.

## 5. 권장 개선 순서

1. **규칙 신뢰성:** 상태효과 턴 순서, 무효 물약, maxMP 장비, 상인 보스 AI를 고치고 각 항목에 회귀 테스트를 추가한다.
2. **모바일 플레이 가능성:** 가로 overflow를 제거하고 모바일 HP/MP/상태/스킬바를 제공한다.
3. **생성 안정성:** 단일 occupancy 검사와 안전 순간이동을 도입하고, seed 기반 1,000회 생성 테스트를 돌린다.
4. **접근성:** 모달 포커스/ARIA, 확대 허용, 아이콘 버튼 이름, reduced-motion 동작을 정리한다.
5. **밸런스 패스:** 층별 클리어 시간, 피해량, 회복 소비, 사망 원인, 상점 구매율을 수집해 클래스/보스/메타 성장 곡선을 조정한다.
6. **제품화:** ROT.js 고정·로컬화, 코드 모듈화, CI 스모크 테스트, 실행/배포 문서를 추가한다.

## 6. 출시 판단 기준

다음 조건을 모두 만족하면 공개 데모 후보로 재평가할 수 있다.

- 390px 모바일에서 가로 overflow 0, HP/MP/상태/스킬 4개를 모두 조작 가능
- 상태효과 1/2/3턴 자동 테스트 통과
- 모든 카탈로그 아이템의 설명-동작 계약 테스트 통과
- 장비 착탈 시 HP/MP/ATK/DEF/CRIT 파생값 테스트 통과
- seed 1,000개에서 핵심 엔티티 좌표 중복 0건, 계단까지 도달 가능 100%
- 키보드만으로 모든 모달 진입·선택·닫기 가능, 활성 모달의 접근성 트리 노출 확인
- CDN 차단 상황에서도 실패 안내 또는 로컬 fallback 제공
